# Everything UI concept

A self-contained, responsive interface prototype. Open `dist/index.html` through a static HTTP server.

The concept covers sign-in, a Home dashboard, agent selection, editable agent names, creating agents, messaging, shared artifacts, and notification onboarding. Sign-in lands on Home, where incoming updates are the main focus and recent conversations are ordered by the user's latest interaction (up to five). Updates use compact rows with the agent's icon and name, a two-line message preview, timestamp, unread indicator, and message-type icon. The whole row opens the corresponding conversation for review or reply and becomes read. Home shows up to eight updates; View all opens the complete feed. Your team remains the full directory. Recent ordering and read states persist across reloads, and earlier demo saves are upgraded without replacing conversations or names. The preview toolbar switches screens and offers a 390px phone viewport.

Midnight is the default design, using neutral charcoal surfaces with restrained amber accents for actions, selected items, avatars, and small highlights, paired with Signal's grid artwork and the constellation brand icon. The theme picker offers Midnight, Midnight Dimmed, Graphite, Graphite Dimmed, Daylight, and Sand. The dimmed variants keep their base surfaces and colors while softening bright text; Graphite Dimmed also softens its pale action buttons and highlights. All six share layout, typography, icons, and interaction behavior. On smaller screens, a compact select keeps all six themes accessible. The choice persists across screens and reloads; `?theme=sand` (or another valid theme name) can open a specific variation.

`dist/tokens.css` is the design-token contract: semantic surface, text, action, border, focus, avatar, and overlay colors, plus shared typography and radius tokens. Components, dialogs, the example artifact, and preview controls consume those roles instead of embedding palette colors. Each theme implements the same roles. The production React/Tailwind application should preserve this approach and multiple-theme support.

At sign-in, the page and its existing grid remain still. Only the routed line in the artwork lights up, tracing its original path. Once that short highlight finishes, the login fades into Home over 300ms. The sequence lasts about one second and uses the same static artwork on phones. Content navigation keeps the established 465ms directional slide and fade without a grid overlay. Content moves 64px on desktop and 38px on phones inside stationary clipping frames, keeping workspace navigation fixed and avoiding page scrollbar flashes. Content and conversations retain normal scrolling. Opening an update briefly marks the exact message and focuses the reply field. Shared-work panels and dialogs have a short entrance. Select Sign in in the preview toolbar and submit the demo form to replay the entrance.

Artifacts open in a non-modal split view beside the conversation. The main content makes room for the artifact, so chat remains visible and usable. Drag the divider or use its arrow keys to adjust the split; each pane scrolls independently. On narrow screens the panes stack with a horizontal divider. The selected split is remembered. Close or Escape restores the main content width, while Open in new tab opens the same artifact separately with the active theme. Drafts remain intact, and sending messages keeps the artifact open. Agent editing and notification settings retain their existing dialogs.

`dist/motion.js` decorates synchronous screen changes with the Web Animations API. Outgoing snapshots are inert, hidden from assistive technology, and removed when animations finish or navigation interrupts them. Rapid navigation replaces the current transition. Reduced-motion preferences skip these effects, and message rerenders do not replay the entire conversation history. No animation library is required.

This is design exploration, not the Everything application. Sign-in, agent replies, activity, and notification states are simulated. No credentials are read or persisted. Demo agent definitions, messages, the notification toggle, and the selected theme are saved in browser local storage. Reset demo clears agent and conversation state while retaining the theme. No Pi, Fleet, Keycloak, or live push service is connected.

The model-provider control beside notification settings (also available in conversations) shows a simple red plug outline when disconnected. It opens a “Power your agents” provider list, currently offering only ChatGPT. Connecting changes the control to the green ChatGPT logo. Reopening it shows the connected provider, usage link, and Disconnect action; disconnecting returns to the provider list. Status labels are available to assistive technology. The dialog uses the approved **Continue with ChatGPT** formats: black with white text and logo for dark themes, white with black text and logo for Daylight and Sand. The button retains a 242×45px button, 12px radius, 21px official SVG logo, and Inter Medium. The supplied vector geometry is reused as a colored mask for the toolbar status. Button colors and the official SVG variant are dedicated brand tokens that update immediately when the theme changes; connection status uses semantic tokens with light/dark variants.

This is a simulated connection: the button only changes the selected `demoProvider` in local storage. Disconnect and Reset demo clear that state. Earlier ChatGPT-only preview connections migrate automatically. No OAuth redirect, token, account identity, or plan authorization is implemented. Connection changes preserve the active chat draft and artifact pane. The Manage usage link opens the real ChatGPT usage settings in a separate tab. A real implementation must connect this button to the selected ChatGPT plan authorization flow and derive status from its actual account session.

Brand references: [approved button formats](https://developers.openai.com/siwc/website) and [plan usage UI guidelines](https://developers.openai.com/siwc/ui-ux-guidelines). Assets are vendored without geometry changes from `https://developers.openai.com/assets/siwc/sign-in-buttons/chatgpt-logo-white.svg`, `https://developers.openai.com/assets/siwc/sign-in-buttons/chatgpt-logo-black.svg` and `https://developers.openai.com/fonts/siwc-inter/Inter-Medium.ttf`.

The proposed production application remains React with Tailwind as agreed. This prototype uses buildless HTML, CSS, and JavaScript to keep the visual review self-contained.
